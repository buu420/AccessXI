# September 5 release validation

## Source and deployment boundary

The release starts from upstream `885e29746b9da02dd12c07d8d078b9221238a720` in an isolated checkout. The installed reader was authoritative for the newer mission and navigation runtime; current upstream installer, updater and native fixes were retained. Character caches and local configuration were excluded. The original development checkout and its unrelated changes were preserved.

New runtime changes in this release investigation are the Memory Stream object classification guard, bounded automatic support logging and `/axi report`, and a narrow legacy progress migration correction. The migration retains the first action when one old completed step corresponds to multiple material actions. It does not rewind previously persisted v2 progress.

## Native collision artifact

The release uses the existing reviewed collision DLL with SHA-256 `FD6D8A84D168252E1724B4192C541B866BDD6CF369F61C1AB3E764151DEB7095`, matching the committed manifest and ABI 3. A fresh local collision rebuild produced a different hash; the pin was not changed. The reviewed DLL passed its manifest, dependency and reproducible-PE checks. Native PlayOnline components were independently rebuilt; the installer was then packaged with `-NoPayloadBuild` from those staged components and the pinned collision DLL.

## Retail limits

The September 4 Holla log shows a rendered closed Stream, its exact paired Receptacle's defeat, the same Stream rendered open ten seconds later, and later tracking on floor two. This supports the first forward transition only. Full Holla Spire traversal, the other three Promyvion zones and a Holla floor-two wall-contact cluster still need retail investigation. Offline tests do not establish those routes as complete.

The game was closed during deployment. New logging and migration behavior will load on the next launch; neither an installer rerun against the user's installation nor a new retail traversal was performed as part of publication.
