# AccessXI v2026.09.06

The Horutoto Ruins Experiment could keep routing to the Magical Gizmo gate
after its cutscene. The native mission number did not change, an earlier
approach instruction blocked event recognition, and the six-gizmo search was
stored as an informational note with no progression action.

The reviewed gate event now advances to the search. All six Ancient Magical
Gizmos in Lily Tower appear in Objects and in the mission's search choices.
The search ends when the Cracked Mana Orb is acquired; examining an empty gizmo
does not end it. The return identifies the exact Hakkuru-Rinkuru at the Orastery.

Two shared changes address the underlying failure patterns. A narrowly matched,
catalogue-validated search instruction can become a material objective, and a
later visit to the same destination keeps its own route row. Exact reviewed
target bindings also apply to interaction recognition. Unrelated duplicate-name
choices and unobservable progression boundaries retain their existing rules.

An update can recover the already completed gate cutscene from retained local
support logs. Recovery requires the same character, a live mission snapshot,
the exact trigger, event, NPC instruction and interaction end. It never rewinds
a later cursor. Missing or rotated evidence is not treated as completion. Scan
results, event acceptance, cursor migration and search refusals are logged.

from the East Sarutabaruta Lily entrance, and none connect from the West
Sarutabaruta entrance. The Toraimarai entrance also connects geometrically;
the guide's East Sarutabaruta approach remains preferred. These are geometry
checks, not proof of open doors or a completed retail walkthrough. Existing
walking-route validation remains mandatory. Other nation mission coverage gaps
in the September 5 audit are not certified by this release.

## Evidence and reproduction

The submitted support report stays private and is not part of the repository or
installer. The event identity and key-item transition were checked against the
[LandSandBoat mission script](https://github.com/LandSandBoat/server/blob/base/scripts/missions/windurst/1_1_The_Horutoto_Ruins_Experiment.lua)
and the observed retail packet/dialogue sequence. Packet fields were checked
against the [Windower packet definitions](https://github.com/Windower/Lua/blob/live/addons/libs/packets/fields.lua).
The existing Ghidra-derived mission-menu and FFXINAV traces informed the native
state and route-validity boundaries.

Set `ACCESSXI_ADDON` to the reader directory under test. Run
`tools/test_horutoto_objective_progress.lua` with `016`, `017` or `migrated`.
The optional `history <report-path> <character-identity>` mode uses a local
report. Run `tools/test_objective_event_evidence.lua` and
`tools/test_mission_search_steps.lua` for the pure module cases.

[Native measurements](../investigations/2026-09-06-horutoto-search-ingress.tsv)
and [input hashes](../investigations/2026-09-06-horutoto-native-inputs.tsv) are
included. To remeasure, use the first 14 columns as input to
`ingress_probe.exe <FFXINAV.dll> <mesh-directory> <cases.tsv> <output.tsv>`.

Automatic mission and zone diagnostics remain enabled. `/axi report` exports
the support report for further mission or zone investigations.
