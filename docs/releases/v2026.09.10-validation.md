# AccessXI v2026.09.10

FFXI's September 10 update left inventory counts and selection IDs working,
but item names were silent. The game moved the selected native name pointer
from `0xCC8` to `0x14C8`; the current official Ashita offsets still use `0xCC8`.

AccessXI now identifies the reviewed layout from two independent native code
signatures during startup and updates Ashita's selected-name offset cache.
Missing, duplicate, disagreeing or unreviewed signatures leave it untouched,
as do custom offset values. Older clients retain their working layout. The
reader continues to use native visible labels and records the adjustment or
refusal in the automatic support log. No game or offset configuration files
are patched.

The installer includes official Ashita core **4.3.1.2** and Addons **4.20** from
upstream commit `2e4b9c86de538ecfedabab918537c550d6378aaa`. Ashita's release tag
lags behind that download. The local test installation was updated from
4.3.0.2 while the game was closed, with the original files backed up. Existing
AccessXI startup settings and the LuaJIT library compatibility repair remain.

Build scripts now accept `-WindowerResourcesRoot`, preserving the previous
default while allowing builds from an existing resource directory. Migration
tests model a running or closed PlayOnline process instead of depending on
the developer's actual game; both refusal and successful migration are tested.
The installer's real running-game protection remains unchanged.

## Validation

- Reproduced the missing native label before the fix. The new reader regression
  changed from 10 passing / 15 failing assertions to **25 passing / 0 failing**.
  It covers native labels, cursor movement, old/new layouts, ambiguity, custom
  offsets, unknown layouts and scanner/cache failures. The installed copy also
  passes all 25 assertions.
- Existing inventory availability and all-container tests: **29** and **20**
  assertions passed. Scroll long-name and native item-sort checks passed.
- Support writer, automatic logging and report export integration passed.
- Updated reader compiles under Lua 5.1; metadata startup compatibility passed.
  The 159-module forward-scope audit has no clashes. The full reader audit
  reports the same four pre-existing names as the unchanged installed baseline;
  this change introduces no additional forward-scope clashes.
- Ghidra decompilation and independent byte scans corroborate both unique
  signatures in the old and updated clients. Claude reviewed the implementation
  and regression test and reported no blockers.
- Live startup at 14:24:52 on September 10 confirmed
  `status=ready previous=0xCC8 detected=0x14C8 reason="applied"` under the updated
  Ashita runtime. The user then tested Inventory and confirmed
  item-name reading works in the game.
- The live support log records recovered native names across cursor changes,
  including Happy Egg, Yew Wand, Prism Powder, Silent Oil and Ether +1. The
  generic entry-label/help pointers remain zero, confirming that the native
  selected-name correction is what restored reading.
- Installer package, native structure, legacy cleanup, native migration,
  public guide, executable and public-release hygiene checks passed. All eight
  updater behavior tests passed, including digest and path validation.

Native evidence and the exact signatures are documented in
`docs/investigations/2026-09-10-inventory-name-layout.md`. Private support logs
and game binaries are excluded from the public release.
