# AccessXI v2026.09.17

This update restores item descriptions after the September retail FFXI update,
speech in the character action popup opened from `/sea all`, and access to the
Treasure Pool command, item list and Lot/Pass choices. It also adds native speech
for both sides of player-to-player trades.

## Item resources

The previous installation spoke native item names but returned no item
descriptions or static details. Ashita 4.3.1.2 could not decode the updated
retail item DAT layout. The installer now includes official Ashita **4.3.2.1**
core and CLI, with the matching DAT map and pointer configuration from upstream
commit `4171c74c8ddb2ca2a31654f199e6c1cee40d7256`.

Ashita's [4.3.2.0 parser correction](https://github.com/AshitaXI/Ashita-v4beta/commit/677f783c419a33608cf8fe7e1dff3a23940baf88)
updates item structures and alignment, adds the new general-item DAT and fixes
the client-version pointer. The subsequent
[4.3.2.1 correction](https://github.com/AshitaXI/Ashita-v4beta/commit/4171c74c8ddb2ca2a31654f199e6c1cee40d7256)
fixes the new item-slip field offset. This runtime requires retail FFXI client
**30260904_1 or later**.

The earlier native item-name correction remains unchanged. The prior Ghidra
trace and the current startup log both support the reviewed `0x14C8` layout;
this release makes no additional inventory-layout changes or item-data fallback.
See [the native inventory investigation](../investigations/2026-09-10-inventory-name-layout.md).

## Search character actions

The `scoption` reader existed, but its loader passed the callback table at the
wrong level. The module expected `search_player_options_context` and instead
received an empty context. Its default pointer checker always returned false,
and its default logger discarded the reason. The user heard the unsupported
window announcement even though the search result itself read correctly.

The loader now supplies the named context. The existing reader again uses the
native cursor, selected entry and `entry + 0x40` help text. Pointer validation,
conditional rows and refusal of missing native text remain unchanged. Successful
reads and specific quiet reasons now reach the automatic support log.

The old test supplied a correct environment by hand, so it missed this wiring
defect. The regression now executes the production loader, context provider and
actual call site together, then checks speech, cursor state, timestamps and
success/refusal diagnostics. It failed on the old code and passes with the fix.

## Treasure Pool

The self command menu now resolves the native command ID rather than assuming
fixed row positions. The September 17 10:36:28 capture showed the self menu's
child command array as `5,8,7,25,9,19,12,10`: Treasure Pool was command 12 on
row 7, and the user-identified bottom Check was command 10 on row 8.

When Treasure Pool disappeared, Check moved to row 7 and the earlier fixed
mapping misread it as Treasure Pool. The production regression reproduced that
failure. The self-menu resolver now uses the already-read native ID at
`child + 0x1A + selected * 2`, bounded by the visible count, and shares the
DAT-backed command-ID mapper used for other targets. ID 12 maps to Treasure
Pool; ID 10 remains Check. Missing or unknown IDs never fall back to a row guess.
The test covers the pool appearing, disappearing, other optional rows moving,
and stale entries beyond the visible list. At 11:11:43 the deployed reader
logged row 7 as ID 10, Check, followed by matching speech.

The new menu module reads the highlighted item from the game's rendered list.
Ghidra on the September client established these boundaries:

- `1013EBE0` sorts the displayed treasure records by drop time; `1013EE10`
  renders them. Count is the child object's unsigned word at `+0x15C` (0–10),
  not the generic object's capacity of 12. Records begin at `+0x1C`, stride
  `0x20`; item ID, quantity, local lot and original pool slot are at `+0`,
  `+2`, `+4` and `+6`. The parent cursor is at `+0x4C`.
- `1013F340` copies the selected record into the `menu lootope` child and
  opens that exact name. `1013F460` maps cursor 1 to Lot and cursor 2 to Pass.
  Those branches call the client senders for opcodes `0x041` and `0x042`,
  respectively, matching the [Windower packet definitions](https://github.com/Windower/Lua/blob/dev/addons/libs/packets/fields.lua).
- `1013E880` refuses the popup for passed rows. `1013F3C0` applies widget
  operation 5 to row 1 for an existing positive local lot. The condition is
  proven; interpreting operation 5 as disabling Lot is corroborated by the
  native dimmed state. Speech marks that option unavailable.

The reader validates both parent/child ownership links, count, cursor and
item ID. The raw pool slot is one byte; its padding byte is ignored. Missing
optional quantity, lot or pool-slot details do not suppress the item name or
action. Item names use the resource ID rendered by the client; it never
assumes that cursor minus one is the raw pool slot. Success and quiet refusal
reasons enter the automatic support log. Reading never sends a Lot/Pass action.

Focused tests exercise the production loader and dispatcher, sorted rows with
different pool slots, changing cursors, quantity and passed state, empty pools,
bad pointers/ownership/counts/records, missing item names and both popup choices.
The command-order and missing-menu regressions failed before their corrections.

## Player trades

The NPC handover reader did not cover `menu trade` or `menu gift`. Both player
trade panes therefore fell through as unsupported. The new module reads the
currently focused pane and its native cursor at `object + 0x4C`; the generic
query reported unrelated cursor values and widget capacities.

Ghidra traced the September client (SHA-256
`e47ddc426b1c84b643732e615390507c75e56da46c1afd8c4794b238f84a752a`):

- Own-offer render `101513D0` reads eight item records at inventory buffer
  `+0x194C0 + slot * 8`: quantity is u32 at +0 and item ID u16 at +4.
  Record zero holds gil, subject to the renderer's ID/index validity check.
  Input `101515E0` and table `10371D60` map rows 1–8 to slots, 9 to Okay,
  10 to Cancel, and 11 to gil.
- Other-offer controller is registry `10372C78` → global `105781E8`,
  vtable `10336468`. Render `10138FF0` and focus update `10139140` use
  inventory `+0x19308 + slot * 0x2C`: item ID u16 at +0 and quantity u32 at
  +4. The gil amount is u32 at `+0x1930C`. Table `1036F9BC` maps rows 1–8
  to slots and 11 to gil, with no Okay/Cancel rows on that pane.
- Ashita's installed inventory pointer signature matches the client global
  `104DFD98`. The reader follows that managed pointer and validates both
  dereferences rather than embedding a process address.

Speech identifies “Your offer” or “Other player's offer”, the native slot,
item name, quantity, empty state, gil amount or focused button. It uses live
offer records and does not mix the two sides through the older packet cache.
Changing an offer changes its speech identity even if the cursor stays put.
Unavailable item information is announced with its side and slot, and the
reason is logged. This module performs reads only; NPC handovers keep their
existing reader.

The production-loader and dispatcher regression failed before implementation.
Tests cover both record layouts, separate parent objects, different items on
the two sides, updates without cursor movement, empty sentinels, large gil
amounts, control mapping, invalid selections and missing pointers/resources.

## Packaging

Build tools accept `-SharedAssetsRoot` so a checkout can use an explicit shared
dependency directory. The default remains the repository root. Packaging skips
personal addons when copying Ashita, copies the shared addon libraries, and
takes the reviewed addon from the repository directly. This avoids the former
copy-then-delete stage and preserves the separate installed test copy.

The module release gate now covers `load_menu_code_module` as well as data
modules. Its regression proves a missing executable menu reader fails packaging
with the exact missing path, and a present reader is accepted.

The final payload resolves **72** module references and required navigation
inputs. Package structure, public guide, native ASI structure, legacy cleanup,
native migration, public release hygiene and all **8** updater behavior checks
passed. The self-contained Windows installer built successfully. Its extracted
managed assembly matches the build output, and hashing its embedded ZIP proves
it contains the exact separately published payload. The payload's updated
Ashita files match upstream, and all changed reader files match the installed
test copy byte for byte.
